# AI 正文与翻译不能一次完成：排查记录

## 当前结论

尚无用户实际失败轮次的请求记录，不能断言 AI 服务本身不稳定。
本地模拟已复现：21 段英文、翻译并发为 1，第二次请求丢失响应后，
只完成 1 段，其余请求被阻止。已确认失败（HTTP 400、无效结构、改写原文）
则只影响当前段，其余 20 段完成。补做复用成功段，未确认请求仍需授权。

主流程会保留原文、发布可读的部分笔记；出现笔记不等于 AI 全部完成。
一个请求未知会阻止后续云端工作，包括摘要，避免重复发送已处理但未收到响应的内容。
这能解释“服务测试正常，但整课经常需要补做”的一种路径，仍需实际日志确认。

## 已检查的环节

| 环节 | 当前行为 | 如何识别 |
| --- | --- | --- |
| 分段与并发 | 正文每批最多 20 段；翻译每段一个请求；默认并发 8、上限 16 | `ai_stage_start` 的 segments、batch_size、workers |
| 传输 | 300 秒超时；建连失败可重试；已发送但响应不完整记为 uncertain | `http_attempt` 的耗时、status、definitely_unsent；`receipt` |
| 限流与服务错误 | 429 有界重试；5xx 使用配置的有界重试，耗尽后按未知结果处理 | `http_attempt`、`http_retry`、收据 attempt |
| 响应契约 | HTTP 200 仍需验证 JSON、段落 ID、译文字段及原文未被改写 | `chat_validation` 的 valid、validation_error |
| 输出截断 | 长输入可能触及输出限制；原有解析可能拒绝截断内容 | finish_reason、completion_tokens、content_chars；本次不改解析策略 |
| 请求被阻止 | 已存在 uncertain 或旧 Sending 收据时阻止后续派发 | `request_blocked` 指向 blocked_by；`blocked` |
| 本地跳过 | 汉字占比启发式跳过翻译；不代表服务返回了译文 | `chunk` 的 local_language_skip、统计 local_skipped |
| 截图缺失 | 视觉正文处理所需截图不可用时保留原文 | `chunk` 的 image_unavailable |
| 保存与回滚 | AI 结果没有可读正文时回滚；最终笔记可能是 partial | `body_rollback`、`done.partial`、`run_result` |

原来的 `warn_once` 只展示首个分块错误；桌面任务日志仅保留 200 条，
NDJSON 日志格式器还会在 message 存在时舍弃结构化字段。
因此原日志不适合分析完整轮次。本次独立导出结构化事件，绕开这些信息损失点。

## 获取一轮日志

每次建立任务执行上下文时，自动导出一个独立文件，无需开启调试模式：

`<课程库>/.course2md/work/<任务 ID>/diagnostics/round-<Unix毫秒>-<随机标识>.jsonl`

传统 CLI 转换在其任务 `.work/<任务 ID>/diagnostics/` 下使用相同文件格式。
路径也写入本轮普通日志的 `AI diagnostics:` 行。补做使用新任务目录；
同一任务暂停后继续或重新启动会新建轮次文件，不覆盖之前的文件。
复制对应 JSONL 文件即可提供这一轮诊断；比较补做效果时，同时提供原任务及补做任务的文件。
以前运行的历史无法补录网络耗时和重试过程，需要使用含本改动的核心程序重新运行。

记录包括相对毫秒时间、请求指纹与尝试编号、时间段范围、HTTP 状态和耗时、
响应大小、固定 finish_reason 分类、数字 token 用量、响应校验原因、
本地跳过/复用/失败/未知段数，以及阶段与最终发布事件。
不导出 API Key、服务 URL、模型名称、提示词、正文、图片或服务响应原文。
不要将 `requests/*.json` 当作同等脱敏日志分享，其中会保留成功的课程内容。

`run_result.ok = true` 仅表示流水线正常返回，AI 是否全部完成要看
`ai_stage_result.failed/uncertain` 与 `done.partial`。
`round_closed` 仅表示执行上下文释放，不代表成功；缺失它可能是进程被终止。
文件创建或写入失败会告警，但不阻止课程处理。日志逐行追加，不自动清理历史轮次。
